多任务容器

## 当前架构限制

当前任务管理系统采用**单任务栈模型**，通过 `ClineProvider` 维护 `clineStack: Task[]`，同时只能有一个活跃任务 [1](#0-0) 。创建新任务时会调用 `removeClineFromStack()` 清除现有任务（除非是子任务） [2](#0-1) 。

Webview 是单实例，通过 `postStateToWebview()` 同步单一任务状态 [3](#0-2) 。消息处理在 `webviewMessageHandler` 中串行执行 [4](#0-3) 。

## 重构方案

### 1. 多任务容器

将 `clineStack` 替换为 `TaskManager`，支持并发任务：

```typescript
class TaskManager {
	private tasks: Map<string, Task> = new Map()
	private activeTasks: Set<string> = new Set()

	async createTask(options: CreateTaskOptions): Promise<string> {
		const task = new Task(options)
		this.tasks.set(task.taskId, task)
		this.activeTasks.add(task.taskId)
		return task.taskId
	}
}
```

### 2. 多窗口管理

扩展 Webview 系统支持多实例：

- 在 `ClineProvider` 中管理多个 `WebviewView` 实例
- 每个任务绑定独立的 Webview
- 实现 `TaskWindowRegistry` 跟踪窗口-任务映射

### 3. 任务间通信

添加任务消息传递机制：

```typescript
interface TaskMessage {
	fromTaskId: string
	toTaskId: string
	type: "task_request" | "task_response"
	payload: any
}
```

在 `webviewMessageHandler` 中新增消息类型：

- `sendTaskToWindow`: 向指定窗口发送任务
- `taskCompleted`: 任务完成通知

### 4. 并发安全

- 使用 `Mutex` 保护共享状态访问
- 任务状态更新改为原子操作
- 消息队列按任务ID隔离（参考现有 `MessageQueueService`） [5](#0-4)

### 5. 生命周期协调

扩展 `Task` 类添加等待机制：

```typescript
async waitForSubtask(taskId: string): Promise<TaskResult> {
  return new Promise((resolve) => {
    this.on('subtaskCompleted', (result: TaskResult) => {
      if (result.taskId === taskId) resolve(result)
    })
  })
}
```

## 实现路径

1. **重构 ClineProvider**：替换栈为任务管理器，支持多任务并发
2. **扩展 Webview**：实现多窗口创建和管理
3. **添加通信协议**：定义任务间消息格式和处理
4. **更新 UI**：修改 `ChatView` 等组件支持多任务窗口
