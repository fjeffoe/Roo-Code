## 多任务并发运行方案

Roo Code当前采用**单任务栈模型**，要改为多任务并发运行需要重构任务管理系统。

### 当前架构限制

系统目前通过`clineStack`数组维护任务栈，确保同时只有一个活跃任务 [1](#2-0) 。创建任务时会强制移除栈顶任务（除非是子任务） [2](#2-1) 。

### 实现多任务并发的方案

#### 1. 修改任务存储结构

将任务栈改为任务映射表，支持多个并发任务：

```typescript
// 当前: clineStack: Task[]
// 改为: activeTasks: Map<string, Task>
// 添加: taskQueue: Task[]
```

#### 2. 任务调度器实现

创建任务调度器管理并发执行：

```typescript
class TaskScheduler {
	private maxConcurrentTasks = 3
	private activeTasks = new Map<string, Task>()
	private taskQueue: Task[] = []

	async scheduleTask(task: Task): Promise<void> {
		if (this.activeTasks.size < this.maxConcurrentTasks) {
			await this.startTask(task)
		} else {
			this.taskQueue.push(task)
		}
	}

	private async startTask(task: Task): Promise<void> {
		this.activeTasks.set(task.taskId, task)
		task.on("completed", () => this.onTaskCompleted(task.taskId))
		await task.startTaskLoop()
	}
}
```

### 关键修改点

1. **ClineProvider重构**: 移除栈模型，实现任务调度器 [3](#2-2)
2. **Task类改造**: 增加资源隔离和并发控制
3. **消息处理扩展**: 支持任务间通信和状态同步 [4](#2-3)
4. **事件系统增强**: 扩展任务生命周期事件 [5](#2-4)

### 注意事项

- **API速率限制**: 需要全局速率限制管理器避免超出提供商限制
- **文件操作冲突**: 实现文件锁机制防止并发写入冲突
- **内存管理**: 限制并发任务数量避免内存溢出
- **用户体验**: 提供清晰的任务切换和状态指示

## Notes

- 当前系统已支持子任务机制，可作为多任务实现的基础
- 测试用例显示系统具备处理多个任务的能力 [6](#2-5)
- 需要仔细设计资源隔离和状态同步机制
- 建议先实现有限并发（如2-3个任务）再逐步扩展
